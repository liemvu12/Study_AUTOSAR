# QUY TẮC PHÁT TRIỂN & QUY TRÌNH SỬA ĐỔI MÃ NGUỒN AUTOSAR
## (AUTOSAR Development Golden Rules & Engineering Workflow Guidelines)

> **Mục đích:** Thiết lập các quy tắc bất di bất dịch (Golden Rules) trong quá trình thực hành, phát triển và sửa đổi mã nguồn AUTOSAR, đảm bảo tuân thủ tiêu chuẩn kỹ nghệ tại các hãng xe (OEM) và Tier-1 (Bosch, LG VS, VinFast, Hyundai Kefico, Vector, Elektrobit).  
> **Áp dụng cho:** Toàn bộ 27 Hands-On Tasks và các dự án thực tế.  
> **Vị trí thư mục:** `docs/hands_on_tasks/task_fix/`

## 1. 🛑 3 QUY TẮC VÀNG BẤT DI BẤT DỊCH (GOLDEN RULES)

### 🔴 QUY TẮC 1: TUYỆT ĐỐI KHÔNG CHỈNH SỬA MÃ SINH TỰ ĐỘNG (AUTO-GENERATED CODE)
* **Các file bị cấm sửa:** Toàn bộ file có tiền tố hoặc hậu tố `*_Cfg.c`, `*_Cfg.h`, `*_PBcfg.c`, `*_LCfg.c`, `Rte.c`, `Rte.h`, `Rte_*.h`, `Os_Cfg.c`, `Os_Cfg.h` nằm trong thư mục `build/.../config/`.
* **Lý do kỹ thuật:**
  1. **Bị ghi đè (Overwritten):** Mỗi khi cấu hình hệ thống thay đổi (thêm signal CAN, đổi chu kỳ task, thêm DTC), quá trình **Code Generation** sẽ chạy lại và **xóa sạch toàn bộ nội dung sửa tay**.
  2. **Gây lỗi ẩn trong nhóm (Silent Team-level Bugs):** Khi đưa code lên Git, các thành viên khác re-generate trên máy của họ sẽ làm mất bản vá tay của bạn, dẫn đến crash hệ thống không rõ nguyên nhân.
  3. **Dấu hiệu nhận biết:** Luôn có cảnh báo ở đầu file:
     ```c
     /* =========================================================================
      * !AUTOGENERATED FILE - DO NOT EDIT!
      * Any manual modifications to this file will be LOST on next generation.
      * ========================================================================= */
     ```

---

### 🔴 QUY TẮC 2: FILE CẤU HÌNH (ARXML / XML) LÀ NGUỒN CHÂN LÝ DUY NHẤT (SINGLE SOURCE OF TRUTH)
* Mọi tham số hệ thống (Baudrate CAN, ID tin nhắn, Kích thước PDU, Độ ưu tiên Task, Mã lỗi DTC, Phân vùng bộ nhớ NvM) **bắt buộc phải được định nghĩa trong file cấu hình ARXML/XML**.
* **Tuân thủ tiêu chuẩn ASPICE & ISO 26262:** Nếu code C chạy một tham số khác với file ARXML đặc tả, chuỗi liên kết nguồn gốc (Traceability) bị đứt gãy $\rightarrow$ **Trượt đánh giá kiểm toán an toàn (Audit Fail)**.

---

| Vùng Mã Nguồn | Ví Dụ File / Thư Mục | Quyền Chỉnh Sửa | Cách Sửa Đúng Quy Chuẩn |

## 3. 🧩 CƠ CHẾ TÙY BIẾN HỢP LỆ: CALLOUTS & HOOKS

Khi một module BSW cần sự can thiệp từ người phát triển (ví dụ: khởi tạo ngoại vi trước khi OS chạy, hoặc xử lý khi hệ thống crash), AUTOSAR không yêu cầu bạn sửa mã lõi BSW mà cung cấp sẵn các **Callout Stubs**:

### Ví dụ 1: EcuM Callout Hooks (`EcuM_Callout_Stubs.c`)
* BSW sinh ra lời gọi hàm: `EcuM_AL_DriverInitZero()` và `EcuM_AL_DriverInitOne()`.
* Kỹ sư cài đặt phần cứng cụ thể trong file ngoài:
  ```c
  /* File: EcuM_Callout_Stubs.c (Do kỹ sư viết - KHÔNG BỊ GHI ĐÈ) */
  void EcuM_AL_DriverInitZero(void) {
      Mcu_Init(&Mcu_Config);
      Port_Init(&Port_Config);
  }
  ```

### Ví dụ 2: OS Error Hooks (`Os_Hooks.c`)
* Khi OS gặp lỗi (Task quá tải, Stack Overflow), nhân OS gọi hàm `ErrorHook(StatusType Error)`.
* Kỹ sư implement việc log lỗi hoặc reset ECU an toàn trong file này.

## 4. 📁 HƯỚNG DẪN QUẢN LÝ FILE DIFF TẠI `task_fix/`

Thư mục `docs/hands_on_tasks/task_fix/` được dùng làm nơi lưu trữ các bản vá (patch/diff), ghi chú sửa đổi và bằng chứng hoàn thành cho từng task trong lộ trình 27 tasks:

### Cấu Trúc Đề Xuất:
```
docs/hands_on_tasks/task_fix/
├── rule.md                         ← File quy tắc này (tham chiếu gốc)
├── task_01_architecture.diff        ← Diff code của Task Chuyên Đề 01
├── task_02_os_mcal.diff             ← Diff code của Task Chuyên Đề 02
├── task_03_comstack.diff            ← Diff code của Task Chuyên Đề 03
├── task_04_diagnostic_memory.diff   ← Diff code của Task Chuyên Đề 04
├── task_05_toolchain.diff           ← Diff code của Task Chuyên Đề 05
└── task_06_realworld_bms_vcu.diff   ← Diff code của Task Chuyên Đề 06
```

### Cách Tạo File Diff Sau Khi Hoàn Thành Mỗi Task:
```powershell
# Chạy tại thư mục gốc Study_AUTOSAR-main:
git diff as/ > docs/hands_on_tasks/task_fix/task_02_os_mcal.diff
```
